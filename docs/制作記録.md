## 2. 制作の流れ（時系列）

### フェーズ1: 手稲区パイロット（町丁目別の設置率マップ）
1. e-Stat から手稲区の小地域境界と一戸建世帯数を取得。
2. 建物外周線から戸建てサイズ（建築面積 50〜250㎡・コンパクト形状）を抽出。
3. 国土地理院のシームレス空中写真（z18）で屋根を切り出し。
4. オープンソースの太陽光パネル検出モデルで判定。
5. 町丁目ごとに集計し、GeoJSON と folium 地図を出力。
6. 判定精度を**100件目視確認できるページ**を作成。

**結果**: パイプラインは最後まで動いた。ただし **AIの的中率は約5%** で実用外（後述）。

### フェーズ2: 北海道全域の「対象戸数」推計へ方針転換
- 家ごとに築年・屋根形状・太陽光の有無を判定する手段が無いため、**統計から市区町村ごとの割合を作り、戸建て数に掛ける**方式に切り替えた。
- 陸屋根率だけはどの統計にも無いため、**空中写真から150軒を目視ラベルして実測**。

### フェーズ3: 地図の機能追加
- 背景を空中写真に。色分けの濃さスライダー。
- 検索（町丁目・住所・施設）、マイピン、経路（ナビ）。
- 手稲区の家ごとのピン（戸建て候補＋AI判定）と、その場での確認ラベル記録。

### フェーズ4: 築年の家ごとの推定（試作中）
- 2008年度の航空写真に建物があったかで「築20年以内」を推定する方式。原理は確認済み、精度測定のためのラベル待ち。

## 3. 使ったデータと入手方法

| データ | 出典 | 使い方・ID |
|---|---|---|
| 町丁目境界・一戸建世帯数 | e-Stat 統計GIS（国勢調査2020 小地域） | 境界: `dlserveyId=A002005212020`、一戸建: `statsId=T001086`。`code=01`（北海道全体）で一括取得できる。APIキー不要 |
| 持ち家・築年・太陽光（市区町村別） | e-Stat API（住宅・土地統計調査2023） | 表ID `0004021758`（所有×建て方×建築時期）、`0004021627`（所有×建て方×省エネ設備）、`0004021645`（所有×建築時期×省エネ設備）。**アプリケーションID必須（無料）** |
| 2023.10以降の新築 | e-Stat API（建築着工統計） | 表ID `0003114504`（利用関係×構造×建て方、市区町村別、年次） |
| 建物外周線 | 国土地理院 最適化ベクトルタイル `optimal_bvmap-v1`（z16, `BldA`層） | 基盤地図情報由来で同じ種別名。ログイン不要。基盤地図情報GMLはログインが必要で、自動取得していない（GMLがあれば差し替え可） |
| 空中写真 | 国土地理院 `seamlessphoto`（z18, 北海道で約0.44 m/px） | 出典明記が必要（地図に表示済み） |
| 古い空中写真 | 国土地理院 `nendophoto{年度}`（2007年度以降） | 手稲区は2008・2020年度が全域で取得可 |
| 背景地図 | 国土地理院 `pale` / `std` / `seamlessphoto` | OpenStreetMapのタイルは、HTMLを直接開くと**ブロックされる**ため使わない |
| 住所検索 | 国土地理院 AddressSearch（CORS可）／OpenStreetMap Nominatim（施設名） | 北海道内に限定して検索 |
| 経路 | Valhalla（`valhalla1.openstreetmap.de`、日本語案内）、失敗時 OSRM | 公共交通はGoogleマップに引き継ぎ |

> **e-StatのアプリケーションIDは共有しない。** 各自で取得して環境変数 `ESTAT_APP_ID` に設定する（リポジトリには入れていない）。

## 4. 推計のしくみ（対象戸数の出し方）

```
対象戸数 = 一戸建(国勢調査) × 持ち家割合 × 築20年以内割合 × (1−太陽光設置率) × (1−陸屋根率)
          ＋ 2023.10以降の新築 × (1−新築の太陽光設置率) × (1−陸屋根率)
```

1. **一戸建**: 国勢調査2020の町丁目別一戸建世帯数。市区町村の総数に合わせ、秘匿(X)分を世帯数で配分して整合させる（手稲区 33,896 = 区合計と一致）。
2. **持ち家割合**: 住調2023「持ち家一戸建 ÷ 一戸建」（市区町村別）。賃貸はここで除く。
3. **築20年以内割合**: 「2006年以降の築」。住調の区分（2001〜2010年）を、築年×設備表から求めた2006〜2010の比率で按分。
4. **新築（2023.10〜）**: 着工統計の一戸建（持家＋分譲）。`0.25×2023年 + 2024年 + 2025年 + 0.75×2026年`。**2025・2026年は2024年と同水準と仮定**。
5. **太陽光設置率**: 住調の築年別設置率を、小さい市の標本誤差を抑えるため北海道平均へ寄せ（擬似サンプル500）、「一戸建は全体より設置率が高い」補正（0.8〜2.5倍にクリップ）。新築は「2021〜2023.9築」の値を使用。
6. **陸屋根率**: 屋根ラベル150軒の実測（下記）。札幌81%、それ以外56%。
7. **町村（129）**: 住調の市区町村別表は**市（札幌は区）のみ**（北海道全体・札幌市を含め46地域）。町村は「北海道 − 市の合計」（町村部）の割合で代用。
8. **円内の件数**: 区画を面積に応じて1〜25個の点に分け、一戸建数を按分。円に入った点を合計して各市区町村の割合を掛ける。

## 5. 検証・精度

### 5-1. 建物抽出（手稲区）
- 全建物 77,982棟 → 戸建て候補 38,678棟。
- 町丁目別の「候補数」と「一戸建世帯数」の相関 **0.95**、比の中央値 約1.1（物置・店舗等が混ざる分）。

### 5-2. AIによる太陽光判定（手稲区）— **実用に届かず**
- 試したモデル（Hugging Face, MIT）: `finloop/yolov8s-seg-solar-panels`、`Cyrille37/solar-panels-IGN-bdortho`。前者を採用（conf 0.1, imgsz 480）。後者はほぼ無検出。
- 手稲区38,678棟を判定 → パネルあり 1,194棟（3.1%）。
- **目視100件（有効99件）**: あり判定49件のうち正解2・誤り39・判別不能8。**適合率 ≒ 5%（2/41）**。なし判定の見逃しは0/45だが標本が小さく**再現率は決められない**。
- 原因の見立て: 解像度（約0.44 m/px）が粗い、北海道に多い青灰色の鋼板屋根にパネルが紛れる、学習データのドメイン違い。
- → **現在の赤ピンは「確認用の候補」であって確定情報ではない。** 改善策は、ピンの確認ラベルを数百件集めての追加学習。

### 5-3. 陸屋根率（150軒の目視ラベル）
| | 陸屋根/判別可 | 陸屋根率（95%区間） |
|---|---|---|
| 全体 | 45/73 | 62%（50〜72%） |
| 札幌市 | 13/16 | **81%（57〜93%）** |
| 札幌市以外 | 32/57 | **56%（43〜68%）** |

- 150軒の内訳: 判別不能58、陸屋根45、勾配28、住宅でない19。**判別不能が39%**で幅が大きい。
- 札幌は判別可が16軒だけで信頼性が低い。**札幌市で追加ラベルを取るのが最も効く。**
- 全戸建ての値であり、築20年以内に限った値ではない。

## 6. 地図の機能一覧

- **色分け**: 市区町村ごとの対象戸数／対象率。色の濃さスライダー（写真が見えるように）。
- **円で集計**: クリックで中心、半径100m〜20km。内訳と「前段との比（%）」を表示。
- **陸屋根率スライダー**: 札幌／それ以外。全体・円内・CSVに即反映。
- **検索**: 町丁目名（手元データ・即時）→ 住所（国土地理院）→ 施設名（OpenStreetMap）。結果に「半径N m内の対象戸数」。
- **マイピン**: 名前・メモ・色、周辺の対象戸数、ブラウザに保存、CSV/KML（Googleマイマップ用）書き出し・読み込み。
- **経路（ナビ）**: 車・徒歩は地図内に日本語案内つきで描画。公共交通はGoogleマップへ。ピンを順に巡る経路。
- **手稲区の家ごとのピン（試作）**: 戸建て候補（白い点）とAIのパネル判定（赤ピン、スコアで絞り込み）。ピンを押して「あり/なし/不明」を記録→CSV保存（追加学習用ラベル）。

## 7. つまずいた点と対処（再発防止メモ）

| 問題 | 原因 | 対処 |
|---|---|---|
| 最初に取得したのが清田区だった | **区コードの誤り**。手稲区は `01109`、清田区は `01110`（豊平=01105, 南=01106, 西=01107, 厚別=01108） | `config.py` を修正。取得後は範囲（緯度経度）で必ず目視確認する |
| 外部サイトに接続できない | 環境のネットワーク許可が必要 | 環境設定でドメインを許可し、新しいセッションで再開 |
| 背景に「Access blocked」が一面に出る | OpenStreetMapのタイルは、HTMLを直接開く（参照元なし）とブロックされる | 国土地理院のタイルに変更 |
| 住調に町村の表が無い | 市区町村別表は市のみ | 町村部（北海道−市）の割合で代用 |
| 建物が隣のタイルで切れる | ベクトルタイルの余白（80単位）で重複・断片化 | 「重心がタイル本体内」かつ「余白端で切れていない」建物のみ採用 |
| ピン周辺の対象戸数が0になる | 集計関数に経度を渡し忘れ | 修正。数値は別計算（Python）と突き合わせて検証 |
| e-Stat統計GISの取得ファイル | 実体は txt 入りの zip、`X`=秘匿、`-`=0 | ローダーで対応 |
| APIキャッシュが毎回ミス | Pythonの `hash()` は実行ごとに変わる | `hashlib` に変更 |

## 8. 既知の限界

- **家ごとの条件判定はできない**: 築年・屋根形状・太陽光の有無は1軒ごとには分からない。件数は「市区町村の割合 × 戸数」の期待値。
- **面積は建築面積**（外周線の面積）。2階建ては床面積が約2倍になる。
- **小さい円は誤差が大きい**（半径約500m未満、郊外の広い区画）。町丁目内は一様に按分している。
- **住調は標本調査**。小さい市は誤差が大きい。築年の偏り（同じ町丁目内で新しい家が固まる等）は反映していない。
- **新築の2025・2026年は仮定**（2024年と同水準）。
- 築20年は「2006年以降の築」で数える。住調の年区分の都合で近似。
- 経路の所要時間は渋滞・信号を考慮しない。Valhalla/OSRM/Nominatim はコミュニティ運営の無料サーバーで、混雑時は失敗することがある。

## 11. 取り扱いの注意

- **個人情報**: 家ごとのピンは建物の位置情報のみで、居住者の情報は持っていない。営業リストとして使う場合は、特定の個人と結びつく情報を足さないこと。訪問販売には特定商取引法の規制がある。
- **出典表示**: 国土地理院のタイル・データは出典明記が必要（地図に表示済み）。大量取得は負荷を抑える。
- **外部サービス**: 検索・経路は無料の公開サーバーに依存する。業務で常用するなら有償APIか自前サーバーへの切り替えを検討。
- **マイピン**: 各自のブラウザにのみ保存される。共有するにはCSV/KMLで書き出す（チームで使うなら共有保存先が必要）。
